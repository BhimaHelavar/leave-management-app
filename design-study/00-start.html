System design with the Leave Management System

You built a real system with real trade-offs. These notes turn it into a design course: every concept is taught with the LMS, then used on a new system so you can design anything in an interview.

The one idea that connects everything 
Business need ──► Requirements ──► HLD (the big boxes) ──► LLD (classes, rules)
 "approve fast,     functional +      web, api, db,          use cases, pure rules,
  never wrong"      non-functional    queue, cache           interfaces, state machine
                          │                                          │
                          └──────────► Database design ◄────────────┘
                                       tables, keys, constraints, indexes

A senior engineer can walk down this chain (why does this index exist? because screen S-05 needs it, because BR-05 says managers approve) and up it (BR-05 changes: what in the design moves?). That skill is what "architect" means in an interview.

Where each word fits

TermQuestion it answersLMS example
