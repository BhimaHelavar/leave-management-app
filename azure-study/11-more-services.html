Other Azure services (and when you would add them)

The LMS demo needs only three services. These are the others interviewers ask about, each tied to a realistic LMS need. None of them is built into the LMS; this is study material.

Queue vs topic vs event (a classic question)

TypeDeliveryUse
Queue (Service Bus)One consumer gets each message; retries; dead-letter queueDo this task once: send the approval email
Topic + subscriptionsEach subscriber gets a copy"Leave approved" read by payroll and the calendar
Event GridLightweight "something happened" notificationsReact to a blob upload

Service Bus vs RabbitMQ: Service Bus is managed by Azure (no servers); RabbitMQ is open source and portable, you run it yourself (or in a container). Pick Service Bus on Azure unless you must stay cloud-neutral.

Cache-aside example (concept in C#)

// Pseudocode. Not in the LMS; adding Redis needs a package and your approval.
public async Task<IReadOnlyList<Holiday>> GetHolidaysAsync(int year)
{
    var key = $"holidays:{year}";
    var cached = await cache.GetStringAsync(key);
    if (cached is not null) return JsonSerializer.Deserialize<List<Holiday>>(cached)!;

    var fresh = await db.Holidays.Where(h => h.Year == year).ToListAsync();
    await cache.SetStringAsync(key, JsonSerializer.Serialize(fresh),
        new DistributedCacheEntryOptions { AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(12) });
    return fresh;
}

Hard parts to be ready to discuss: invalidation (when data changes), stampede (many misses at once), and "never cache per-user secrets under a shared key".

Container Apps path with the existing Dockerfiles

az acr create -g $RG -n lmsacr$SUFFIX --sku Basic
az acr build -r lmsacr$SUFFIX -t lms-api:1 -f src/LeaveManagement.Api/Dockerfile .
az containerapp env create -g $RG -n cae-lms -l $LOC
az containerapp create -g $RG -n lms-api --environment cae-lms --image lmsacr$SUFFIX.azurecr.io/lms-api:1 --target-port 8080 --ingress external

This is a sketch for learning (I did not run it; the registry needs pull permission set up). The API image listens on 8080 as non-root, matching --target-port 8080.
