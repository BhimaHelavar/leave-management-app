The .NET API on App Service

App Service runs your web app for you: OS, runtime, TLS, restarts. You pay for the plan (the machine); you can run several apps on one plan.

Two ideas first

IdeaMeaning
App Service planThe compute: size, OS (Linux), price tier. F1 = free shared. B1 = small dedicated. S1 adds slots and autoscale.
Web appYour running site on that plan, with its own URL https://<name>.azurewebsites.net, settings and logs.
TierGood forLimits
F1 FreeLearning demoShared, ~60 CPU min/day, no Always On, no custom-domain TLS, no slots, no SLA
B1 BasicSmall real useDedicated, Always On, custom domain + TLS, manual scale
S1 StandardProduction-likeDeployment slots, autoscale, daily backups

I do not quote prices because sources disagreed. Use the Azure pricing calculator for your region.

Step 1: plan and web app

$API  = "lms-api-$SUFFIX"
az appservice plan create -g $RG -n plan-lms-demo --is-linux --sku F1 -l $LOC
az webapp create -g $RG -p plan-lms-demo -n $API --runtime "DOTNETCORE:10.0"
az webapp update -g $RG -n $API --https-only true
az webapp config set -g $RG -n $API --http20-enabled true --min-tls-version 1.2 --ftps-state Disabled
  • DOTNETCORE:10.0 is the Linux runtime string for .NET 10 (LTS). On a Windows plan it would be DOTNET:10.
  • If F1 says "quota is 0" in your region, use another region or request quota. Test this early.
  • Always On is not available on F1. After idle the app unloads; the first request is a cold start (a few seconds).

Step 2: app settings (the cloud version of appsettings and env vars)

Settings you add here become environment variables for your process. In .NET a double underscore means a colon: Auth__Mode = Auth:Mode.

SettingValue on AzureWhy
ASPNETCORE_ENVIRONMENTDemoDev auth is allowed only in Development or Demo. Not Development, so no auto-migrate.
Auth__ModeDevEntraId throws "arrives in 4g" for now
Cors__AllowedOriginhttps://<swa-host>Exactly one origin: the web app. No trailing slash
Auth__Dev__SigningKeyrandom, 32+ charactersSigns the dev JWT. Never reuse a real secret
ConnectionStrings__Defaultthe Azure SQL stringSet as a connection string of type SQLAzure
$WEBHOST = "<your-swa-host>.azurestaticapps.net"      # fill in after the web page step
$KEY = [Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Maximum 256 }) -as [byte[]])

az webapp config appsettings set -g $RG -n $API --settings `
  ASPNETCORE_ENVIRONMENT=Demo Auth__Mode=Dev `
  Cors__AllowedOrigin="https://$WEBHOST" Auth__Dev__SigningKey="$KEY"

az webapp config connection-string set -g $RG -n $API --connection-string-type SQLAzure `
  --settings Default="Server=tcp:$SQL.database.windows.net,1433;Initial Catalog=LeaveManagement;User ID=$ADMIN;Password=$PWPLAIN;Encrypt=True;Connection Timeout=60;"

az webapp config set -g $RG -n $API --generic-configurations '{"healthCheckPath":"/health"}'
Linux detailA connection string saved this way appears to your code as the environment variable SQLAZURECONNSTR_Default. .NET's environment provider maps it to ConnectionStrings:Default automatically, so Program.cs needs no change.

Step 3: build and ship the API

dotnet publish src/LeaveManagement.Api -c Release -o publish
Compress-Archive -Path publish/* -DestinationPath api.zip -Force
az webapp deploy -g $RG -n $API --src-path api.zip --type zip

The exact JSON from /health may differ; the repo returns Status, AuthMode, Database, Environment and TimeUtc.

Step 4: test, then read logs

curl https://$API.azurewebsites.net/health
az webapp log config -g $RG -n $API --application-logging filesystem --level information
az webapp log tail -g $RG -n $API          # live console; Ctrl+C to stop

Container alternative (later)

The repo already has src/LeaveManagement.Api/Dockerfile (port 8080, non-root). You could push that image to Azure Container Registry and run it on App Service for Containers or Container Apps. Use it when you need the exact same image on laptop, CI and cloud, or want scale-to-zero. Not needed for the first deploy.

Deployment slots (concept)

A slot is a second copy of the app (for example staging). You deploy there, test, then swap: the slot goes live instantly with no downtime, and swapping back is a rollback. Needs Standard or higher.
