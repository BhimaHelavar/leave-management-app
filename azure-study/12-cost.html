Cost, limits and cleanup

The demo should cost nothing. These habits make sure it does.

What costs money, and what does not

ItemFree tier behaviourWatch out
Static Web Apps FreeFree planStaying on Free: no Standard features
App Service F1Free, hard CPU quotaCreating a second plan on a paid SKU by accident
Azure SQL free offer100k vCore-seconds a monthBillOverUsage setting; an open SSMS session; a database that was not created with the free flag
Application Insights / Log AnalyticsSmall free ingestion allowanceVerbose logging, no daily cap
Key VaultPay per operation (tiny)Rarely a problem
Redis, Service Bus premium, Front Door, AKSMostly not freeDo not create them for the demo

Habits

  1. Budget first (Basics page). Test the alert email.
  2. After each session open Cost Management → Cost analysis for 30 seconds. Filter by resource group.
  3. Verify the database is really free: az sql db show … --query useFreeLimit must be true.
  4. Tag everything app=lms so unknown costs are easy to find.
  5. Do not leave tools connected to the database.

Cleanup

# list everything first, so you know what will disappear
az resource list -g $RG -o table
# then remove the whole environment (asks for confirmation)
az group delete -n $RG
Destructive commandDeleting a resource group is not undoable. Your rules say to ask before running destructive commands; run this yourself when you are sure. Soft-deleted Key Vaults keep their name for a while (purge protection), so use a different name if you recreate.
