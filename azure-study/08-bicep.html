Infrastructure as code with Bicep

Clicking in the portal is fine to learn, but you cannot repeat it exactly. Infrastructure as code (IaC) describes resources in a file you keep in git, review, and re-run.

What Bicep is

  • A simple language that compiles to an ARM template (JSON). Azure creates what the file describes.
  • Declarative: you say what you want, not the steps. Running it twice changes nothing if nothing changed (idempotent).
  • Alternatives: Terraform (multi-cloud, state file), ARM JSON (verbose), Pulumi (real languages). Bicep is Azure-only and has no state file to manage.

The LMS demo environment

This file creates: App Service plan (F1 Linux), the API web app with settings, SQL server, the free serverless database with auto-pause, the "allow Azure services" rule, and the Static Web App. It compiles cleanly with Bicep CLI 0.49.2 (property names such as useFreeLimit and freeLimitExhaustionBehavior were accepted by the type checker). I did not deploy it to Azure.

// LMS Demo environment. Run at resource-group scope:
//   az deployment group create -g rg-lms-demo -f main.bicep -p sqlAdminPassword=<from a vault> suffix=<unique>
targetScope = 'resourceGroup'

@description('Short unique text so global names do not clash, e.g. your initials + digits')
@minLength(3)
@maxLength(8)
param suffix string

@description('Region for SQL and the API')
param location string = resourceGroup().location

@description('Static Web Apps only exist in a few regions')
param swaLocation string = 'eastasia'

param sqlAdminLogin string = 'lmsadmin'
@secure()
param sqlAdminPassword string

@secure()
param devSigningKey string

var apiName = 'lms-api-${suffix}'
var sqlName = 'lms-sql-${suffix}'

resource plan 'Microsoft.Web/serverfarms@2023-12-01' = {
  name: 'plan-lms-demo'
  location: location
  kind: 'linux'
  sku: { name: 'F1', tier: 'Free' }
  properties: { reserved: true }
}

resource sql 'Microsoft.Sql/servers@2023-08-01-preview' = {
  name: sqlName
  location: location
  properties: {
    administratorLogin: sqlAdminLogin
    administratorLoginPassword: sqlAdminPassword
    minimalTlsVersion: '1.2'
  }
}

resource db 'Microsoft.Sql/servers/databases@2023-08-01-preview' = {
  parent: sql
  name: 'LeaveManagement'
  location: location
  sku: { name: 'GP_S_Gen5', tier: 'GeneralPurpose', family: 'Gen5', capacity: 2 }
  properties: {
    useFreeLimit: true
    freeLimitExhaustionBehavior: 'AutoPause'
  }
}

resource allowAzure 'Microsoft.Sql/servers/firewallRules@2023-08-01-preview' = {
  parent: sql
  name: 'AllowAzureServices'
  properties: { startIpAddress: '0.0.0.0', endIpAddress: '0.0.0.0' }
}

resource swa 'Microsoft.Web/staticSites@2023-12-01' = {
  name: 'lms-web-${suffix}'
  location: swaLocation
  sku: { name: 'Free', tier: 'Free' }
  properties: {}
}

resource api 'Microsoft.Web/sites@2023-12-01' = {
  name: apiName
  location: location
  kind: 'app,linux'
  properties: {
    serverFarmId: plan.id
    httpsOnly: true
    siteConfig: {
      linuxFxVersion: 'DOTNETCORE|10.0'
      alwaysOn: false          // F1 does not allow Always On
      minTlsVersion: '1.2'
      ftpsState: 'Disabled'
      healthCheckPath: '/health'
      appSettings: [
        { name: 'ASPNETCORE_ENVIRONMENT', value: 'Demo' }
        { name: 'Auth__Mode', value: 'Dev' }
        { name: 'Cors__AllowedOrigin', value: 'https://${swa.properties.defaultHostname}' }
        { name: 'Auth__Dev__SigningKey', value: devSigningKey }
      ]
      connectionStrings: [
        {
          name: 'Default'
          type: 'SQLAzure'
          connectionString: 'Server=tcp:${sql.properties.fullyQualifiedDomainName},1433;Database=LeaveManagement;User ID=${sqlAdminLogin};Password=${sqlAdminPassword};Encrypt=True;TrustServerCertificate=False;Connection Timeout=60;'
        }
      ]
    }
  }
}

output apiUrl string = 'https://${api.properties.defaultHostName}'
output webUrl string = 'https://${swa.properties.defaultHostname}'
output sqlServer string = sql.properties.fullyQualifiedDomainName

Run it

az bicep install
az bicep build --file bicep/main.bicep                       # compile only: catches typos
az deployment group what-if -g $RG -f bicep/main.bicep -p suffix=bs92 sqlAdminPassword=$PWPLAIN devSigningKey=$KEY
az deployment group create  -g $RG -f bicep/main.bicep -p suffix=bs92 sqlAdminPassword=$PWPLAIN devSigningKey=$KEY
  • what-if shows what would change before anything changes. Use it every time.
  • Passing passwords on the command line leaves them in shell history. Better: read them from Key Vault (getSecret in a parameter file) or from GitHub secrets in CI.
Known weak points of this file (on purpose, for learning) 1) The SQL password sits in an app setting. Next step: Key Vault reference or managed identity.
2) The firewall rule "allow Azure services" is broad.
3) It does not run migrations. Database schema is still a separate step (SQL page).
4) Static Web App region and SQL free-offer region must be checked in your subscription.

Modules and environments (concept)

When the file grows, split into modules (module sql 'sql.bicep' = {...}) and add a parameter file per environment (demo.bicepparam, prod.bicepparam). Same code, different sizes: F1 for demo, B1 or S1 for production.
