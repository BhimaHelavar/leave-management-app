Interview practice, quiz and glossary

Answer in your own words first, then open the model answer. Use the LMS as your example.

Model questions

1. Walk me through how you deployed your app to Azure.

Angular on Static Web Apps (Free), .NET 10 API on App Service Linux, data in Azure SQL's free serverless database. A manual GitHub Actions workflow builds both parts, writes config.json with the API URL, and deploys. Secrets are in GitHub and App Service settings, not in git. Migrations are an idempotent SQL script I read and run.

2. Why PaaS and not VMs or Kubernetes?

One small API; PaaS removes OS patching and cluster work. I would move to Container Apps or AKS only when several services or special scaling justify the operating cost. The repo already has Dockerfiles, so that path stays open.

3. How does the browser app know the API address on Azure?

At startup it fetches /config.json. The deploy step writes the Azure URL into it. One build runs everywhere; only the small config file changes.

4. What is CORS and how did you configure it?

A browser rule that blocks cross-origin reads unless the server allows the origin. The API allows exactly one origin from Cors__AllowedOrigin. It protects browsers, not the API; real protection is JWT validation and role policies.

5. Where do secrets live?

Not in git (repo-guard scans for it). Demo: App Service settings and GitHub secrets. Better: Key Vault references with a managed identity. Best: no password, e.g. Entra login to SQL and OIDC from GitHub to Azure.

6. What is a managed identity?

An identity Azure creates for a resource and rotates itself. The app gets tokens for other services without storing credentials. You grant it a role at a scope (RBAC), e.g. Key Vault Secrets User.

7. Why OIDC federation instead of a publish profile?

Short-lived tokens, nothing to store or rotate, and the trust is tied to repo and environment. A leaked publish profile works until someone resets it.

8. What are the limits of your free-tier setup?

No SLA. App Service F1 has a CPU quota and cold starts. The SQL free database pauses after 15 minutes and has a monthly vCore-second allowance. Dev auth means the public demo is open unless the API is restricted. These are acceptable for a portfolio, not for real users.

9. How would you add zero-downtime releases?

Move to Standard, deploy to a staging slot, run the health check, swap, and swap back to roll back. Database changes are additive so both versions work during the swap.

10. How do you monitor it?

Health check at /health, Application Insights for requests, failures and dependency timing, KQL queries, and alerts on 5xx and health to an action group. Budget alerts for cost.

11. Service Bus or RabbitMQ?

Service Bus when I am on Azure and want it managed (queues, topics, dead-letter). RabbitMQ when I need portability or already run it. For the LMS approval emails, a queue plus a worker keeps the API fast.

12. What would you change to make this production-ready?

Entra ID auth (4g), Key Vault and managed identity, private endpoint for SQL, B1/S1 with Always On and slots, Bicep for all resources, automated migrations in the pipeline with approval, backups tested, and alerts.

Quick quiz

Answered 0/5

Which service holds the built Angular files?
Static Web Apps hosts static files with free HTTPS.
In App Service, Auth__Mode equals which .NET key?
Double underscore becomes a colon in the environment provider.
Why does the deploy need a separate migration step?
The API's startup initializer is inside an IsDevelopment check.
What does a federated credential prove?
Entra trusts the GitHub token's subject, so no stored secret is needed.
Best fix for a CORS error in the browser?
Exact origin, no trailing slash, right scheme.
