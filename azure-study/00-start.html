Deploy the Leave Management System on Azure

Step by step, with the reason behind every step. After these notes you can deploy the LMS yourself and explain every Azure service you used in an interview.

The goal in one picture

Your laptop today: Angular on localhost:4200, .NET API on localhost:5000, SQL Server LocalDB. On Azure the same three parts live in three different services:

PartLocallyOn Azure (decided in spec T-02)
Web (Angular)ng serve / nginxStatic Web Apps (Free)
API (.NET 10)dotnet run / DockerApp Service on Linux (F1 free now, B1 later)
DatabaseLocalDB / SQL containerAzure SQL Database (free offer, auto-pause)
Build and shipyou, by handGitHub Actions (manual deploy workflow)

How to use these notes

1. Read a page
Each topic goes: what it is, how it works, why, when. Then the exact LMS commands.
2. Play with it
Press Next on the request journey, tick checklists, answer the quizzes. Progress is saved in your browser.
3. Deploy for real
Follow the runbook with the checklist. Copy buttons are on every code block.
Honest status of these notes I wrote the commands from the repo (Program.cs, Dockerfiles, specs) and from Microsoft documentation pages I read. I could not run anything against a real Azure subscription, and I had no .NET SDK or Docker here. The Bicep file compiles with Bicep CLI 0.49.2. Every command is a draft for you to run and check. Where a flag name might have changed, the page says "check with -h".
One real gap you must handle In Program.cs the database migration and demo data run only when the environment is Development. Azure runs as Demo, so nothing creates the tables for you. The SQL page shows two safe ways to do it.
