Architecture: the LMS on Azure

Three services, one pipeline. Press Next to follow a request from the browser to the database.

Why this shape

ChoiceWhyRejected
Static Web Apps for AngularThe built app is only files. Free plan, global CDN, free HTTPS.Running nginx in a container: you pay to serve static files
App Service for the APIYou give it code; Azure handles the OS, patching, TLS, scaling knob. Simplest path for one .NET API.VM (you patch everything), AKS (too heavy for one API)
API called directly + CORSStatic Web Apps Free cannot link an App Service as its API (that needs the Standard plan).Same-origin /api proxy (Standard plan only)
Azure SQL free offerSame engine as LocalDB and SQL Server, no code change, free monthly allowance.Cosmos DB (different model), SQL Server on a VM (you manage it)
Free-tier trade-offs to know App Service F1 is shared: about 60 CPU minutes a day, no Always On (the app sleeps and the first call is slow), no SLA. Azure SQL free: 100,000 vCore-seconds a month and it pauses itself after 15 minutes idle. Good for a demo, not for real users.

Interview line"I chose PaaS (App Service and Static Web Apps) because for one API the managed platform removes patching and server work. If the LMS split into several services I would move the API to Container Apps using the Dockerfiles already in the repo."

IaaS, PaaS, SaaS in one minute

  • IaaS (VM): Azure runs the hardware, you run the OS and everything above.
  • PaaS (App Service, Azure SQL): Azure runs hardware and OS, you bring code and data.
  • SaaS (Microsoft 365): you just use the product.
